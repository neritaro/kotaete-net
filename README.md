# 答えてネット（モダン版）

「答えてネット」を今どきの技術で再構築したものです。プレゼン・授業で、スクリーンに設問を映し、参加者がスマホから回答すると結果がリアルタイムでグラフ表示されます。

## 主な機能

- **ルーム分離**：教員ごとに独立した「ルームID」を持つため、複数の教員が同時に別々の授業で使っても互いに干渉しません
- 選択肢式（棒グラフ表示）／自由記述（一覧表示）／**一言ワードクラウド**（同じ回答が多いほど大きく表示）の3形式
- **匿名／記名式の切り替え**：設問作成時のチェックボックス1つ。デフォルトは匿名
- **CSV／画像エクスポート**：結果をワンクリックでダウンロード。授業後の振り返り資料にそのまま使えます
- **ワンクリックデモ**：ログイン直後に「まずは触ってみる」からサンプル設問（選択式／ワードクラウド）を入力ゼロで即座に開始できます
- **投影モード**：教壇の操作パネルを隠し、QR・コード・結果だけを大きく全画面表示。回答が届くとカウンターが弾む演出付き
- **参加人数のリアルタイム表示**：今何人が参加しているかを教員・学生の両方の画面に表示し、双方向性を体感しやすくします
- **結果観覧ページ（`/watch.html`）**：ログイン不要で結果だけをリアルタイム表示する読み取り専用ページ。紹介サイト等への埋め込みを想定
- QRコードは自動生成（ルーム＋設問コードを直接指すURL）
- **スリープ防止（self-ping）**：ルームが使われている間だけ、アプリ自身が定期的に自分のURLへリクエストを送り、Renderの無料プランが15分無アクセスでスリープするのを防ぎます。授業が終わって一定時間経てば自動的に停止し、夜間・休日は普通にスリープします（無料枠の実行時間を無駄に消費しません）
- DB不要、WebSocket（Socket.io）でリアルタイム同期

## ファイル構成

```
kotaete-modern/
├── server.js         # Express + Socket.io サーバー本体（状態はルームごとにメモリ管理）
├── package.json
└── public/
    ├── index.html    # 学生用回答ページ（"/"）
    ├── screen.html   # 先生用コントロール画面 兼 投影用スクリーン（"/screen.html"）
    └── style.css
```

## ローカルでの動作確認

```bash
npm install
npm start
```

起動したら:
- 投影・先生用: `http://localhost:3000/screen.html`
- 学生用（実際は生徒のスマホで開く）: `http://localhost:3000/`

### 使い方の流れ（教員）

1. `screen.html` を開き、**ルームID**（自分の名前や科目名。半角英数字・ハイフン・アンダースコア、2〜40文字）と**パスワード**を入力してログイン
   - 初めて使うルームIDなら、その場で新規作成されます（別画面での登録は不要）
   - 一度ログインすればルームIDはブラウザに記憶されるので、次回からはパスワードだけで済みます
2. **初めての場合は「まずは触ってみる」からサンプル設問をワンクリックで開始できます**（入力不要）。慣れてきたら通常のフォームから本番の設問を作成してください
3. 設問タイトル・回答形式（選択肢／自由記述／ワードクラウド）・匿名か記名かを設定し「この設問を開始する」
4. 画面にQRコードと回答コード、現在の参加人数が表示される
5. **「投影モードで表示」でQRとグラフだけを全画面表示**（教壇のスクリーンに映すのに最適。Escキーまたは「投影モードを終了」で戻れます）
6. 生徒はQRコードを読み取るか、`http://（サーバーのURL）/` を開いてルームID・コードを入力
7. 回答すると即座に先生画面のグラフ／回答一覧に反映される（回答数のカウンターがポップして届いたことが分かります）
8. 「受付を終了する」で締め切り、結果を**CSVまたは画像で保存**してから「新しい設問を作る」で次の設問へ

### 記名式について

匿名のチェックを外すと、生徒側に「お名前」入力欄が表示され、回答と一緒に記録されます。自由記述の回答一覧には名前が添えられて表示されます（選択肢式の場合、個々の回答者名はグラフには出ませんが、CSVエクスポートには含まれます）。

### 結果観覧ページの使い方（サイト埋め込み等）

`https://（アプリのURL）/watch.html?room=（ルームID）` にアクセスすると、ログイン不要で**そのルームの現在の設問と結果だけがリアルタイムに表示**されます。設問の作成・終了・回答送信はできない、閲覧専用のページです。

用途例：
- 紹介サイト（Google Sites等）にiframeで埋め込み、訪問者に「実際に動いているところ」を見せる
- 別室のモニターに結果だけを映す
- 保護者会・オープンキャンパス等で結果を見せたいが操作はさせたくない場面

**注意**：ルームIDが分かれば誰でも結果を閲覧できてしまいます（パスワード不要）。回答内容を見られたくない授業では、このURLを公開の場に貼らないよう注意してください。

## 無料で授業公開する方法（インターネット経由）

WebSocketを使う常時起動アプリなので、Vercel/Netlifyのようなサーバーレス系ホスティングは不向きです。

### おすすめ: Render（Hobbyプラン / 無料）

クレジットカード登録不要で常時稼働のNode.jsサーバーを無料で動かせます。

### Renderへのデプロイ手順

**手順:**
1. プロジェクトをGitHubリポジトリにpush
2. [render.com](https://render.com) → New Web Service → 対象リポジトリを選択
3. Build Command: `npm install` / Start Command: `npm start`
4. Deployすると `https://（アプリ名）.onrender.com` のようなURLが発行される

**スリープ防止を有効にする（推奨）：**

RenderのWeb Serviceには `RENDER_EXTERNAL_URL` という環境変数が自動的に設定されるため、**追加の設定なしで自己ping機能が有効になります**。動作を調整したい場合のみ、Environment変数を追加してください。

| 環境変数 | デフォルト | 説明 |
|---|---|---|
| `KEEP_AWAKE_HOURS` | `3` | ルームが最後に使われてから、この時間だけ自己pingを続ける |
| `PING_INTERVAL_MINUTES` | `10` | 自己pingの間隔（15分未満にする必要あり） |

例：90分授業を想定するなら `KEEP_AWAKE_HOURS=2` で十分です。デフォルトの3時間のままでも、90分の授業1コマなら問題なくカバーできます。

**注意点：**
- この仕組みは「ルームが使われている間だけ」動作します。誰もログインしていない状態（`lastActivityAt` が0）では自己pingは送信されません
- Render公式にサポートされた機能ではなく、コミュニティで広く使われている回避策（ワークアラウンド）です。将来Render側の仕様変更で効かなくなる可能性はゼロではありません
- 無料プランには月750インスタンス時間の上限がありますが、1サービスを24時間×31日動かしても744時間なので、通常の授業利用でこの上限に達することはまずありません

### 代替: Koyeb（無料・要カード登録）

Renderが使えない場合の代替。1サービスまで無料でスリープなしの常時起動が可能です。

### 学内LAN限定でよい場合

教員のノートPCで `npm start` を実行し、生徒のスマホを教室のWi-Fiに接続、教員PCのローカルIPアドレス（例：`http://192.168.1.10:3000/`）にアクセスさせる方法が最も簡単です。

## ⚠️ 重要な制約（必ず把握してください）

### データはメモリ上のみ・永続化されません

DBを使わない設計のため、**サーバーが再起動するとすべてのルーム・回答データが消えます**。

- 自己ping機能により、**授業中にスリープすることはほぼなくなります**が、それでも以下のケースでは注意してください：
  - 前回のルーム利用から `KEEP_AWAKE_HOURS`（デフォルト3時間）以上空いた場合（例：朝一の授業の前など）→ その場合はスリープしているので、**授業開始15分前に一度URLへアクセスして起こしておく**運用を推奨します
  - Renderのメンテナンスやデプロイのやり直しなど、self-ping以外の要因でプロセスが再起動した場合
- 再起動後、同じルームID・パスワードで再度ログインすればルーム自体はすぐ作り直せますが、**それまでの回答履歴・集計結果は失われます**
- 対策：**設問を締め切ったら、その都度CSVまたは画像でエクスポートしておく**運用を徹底してください

多数の教員に本格展開し、データを永続的に残したい場合は、Render/Koyebの無料DB（PostgreSQL等）を追加する拡張が今後の課題になります。現状はコストゼロ・シンプルさ優先の設計です。

### セキュリティについて

- ルームパスワードは平文でメモリ管理されており、暗号化やレート制限は実装していません。学内の限定的な利用（授業単位の軽い認証）を想定した設計です。機密性の高い情報を扱う用途には向きません
- 生徒からの入力は簡易なバリデーションのみです
